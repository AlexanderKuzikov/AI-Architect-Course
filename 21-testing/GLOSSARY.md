# GLOSSARY — Тестирование

## A–Z

**AsyncDisposable** — интерфейс TS 5.2+, позволяет использовать `await using` для автоматической очистки ресурсов (контейнеров, соединений) после выхода из блока.

**beforeAll / afterAll** — хуки жизненного цикла тест-suite. Выполняются один раз на весь describe-блок. Используются для управления testcontainers: поднять один раз, не на каждый тест.

**beforeEach / afterEach** — хуки, выполняемые перед/после каждого теста. Используются для изоляции данных (truncate, reset state).

**Confidence** — степень уверенности, что тест выявит реальный баг в продакшне. Мок снижает confidence; реальная зависимость повышает.

**Contract testing** — тестирование контракта между сервисами (входные/выходные данные), а не их внутренней реализации.

**Coverage** — процент строк/ветвей кода, выполненных тестами. Метрика отсутствия (< 60% = проблема), не наличия качества.

**E2E (end-to-end)** — тест, проверяющий систему целиком через внешний интерфейс (браузер, API). Медленный, реалистичный, дорогой в поддержке.

**Flakiness** — нестабильность теста: иногда проходит, иногда падает при одинаковом коде. Симптом race condition, внешней зависимости или порядка выполнения.

**Hoisting** — поднятие `vi.mock()` вызовов компилятором Vitest в начало файла до импортов. Статический анализ, не runtime.

**Integration test** — тест, проверяющий взаимодействие нескольких компонентов с реальными зависимостями (БД, HTTP, файловая система).

**Mock** — тестовый двойник, заменяющий реальную зависимость. Возвращает предсказуемые данные, но не проверяет реальное поведение зависимости.

**Mock hell** — состояние тестовой базы, где все зависимости замоканы. 100% coverage, близкая к нулю confidence.

**Playwright Test Agents** — функция Playwright 1.56+: planner/generator/healer loops для AI-assisted authoring и repair тестов.

**Pool (Vitest)** — стратегия изоляции тестовых файлов. `threads` — Worker Threads (default в 4.x, быстро, изолировано). `forks` — child processes (медленнее, полная изоляция памяти). `vmForks` — VM context (для legacy кода с глобальным состоянием).

**Race condition** — ситуация, когда результат теста зависит от порядка асинхронных операций. Основная причина flakiness.

**Retry** — повторный запуск упавшего теста. Маскирует flakiness, не устраняет причину.

**Ryuk** — daemon testcontainers, отвечающий за удаление контейнеров после тестов. В некоторых CI-средах блокируется; отключается через `TESTCONTAINERS_RYUK_DISABLED=true`.

**Supertest** — библиотека для HTTP integration testing. Позволяет отправлять запросы к Express/Fastify app без реального запуска сервера на порту.

**Test Honeycomb** — стратегия Spotify: акцент на service integration tests, минимум unit и e2e. Оптимальна для микросервисной архитектуры.

**Test Pyramid** — классическая стратегия: много unit, меньше integration, мало e2e. Оптимальна для систем с богатой бизнес-логикой и чистыми функциями.

**Test Trophy** — стратегия Kent C. Dodds: акцент на integration tests как наиболее эффективных по соотношению confidence/cost.

**testcontainers-node** — библиотека для запуска Docker-контейнеров из Node.js тестов. Позволяет использовать реальные Postgres, Redis, Kafka и др. без моков.

**Unit test** — тест одного изолированного «юнита» (функция, модуль). Быстрый, но ограниченный по confidence при наличии I/O.

**vi.mock()** — API Vitest для замены модуля тестовым двойником. Хойстится статически, до выполнения импортов.

**vi.mocked()** — обёртка для получения типизированного mock-объекта после `vi.mock()`. Позволяет настраивать поведение в beforeEach.

**Vitest** — test runner от команды Vite. Нативный ESM, Worker Threads изоляция, совместим с Jest API. v4.x требует Node.js ≥ 20.
