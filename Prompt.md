## Структура модуля

Каждый модуль = `README.md` + `GLOSSARY.md`. Один день изучения.

### README.md — разделы по порядку:

1. `# Модуль NN — Название`
2. Blockquote: `> **Для AI-архитектора:** ...` / `> Один день изучения — ...`
3. Содержание — нумерованный список якорей
4. `## Актуальные версии` — таблица с датой
5. Тематические разделы
6. `## Задачи AI-кодеру`
7. `## Чеклист архитектора` — `- [ ]` по категориям

### Структура тематического раздела:

```
## N. Название

### Подраздел
[механика]
[код если нужен]
**Практический вывод для архитектора:** [конкретно]

### Граничные случаи — где ломается
[кейсы с кодом]
**Почему это важно архитектору:** [последствие]
```

Конец модуля:

```
---
*Модуль NN завершён.*
*Следующий: [Модуль NN+1 — Название](../NN+1-папка/README.md)*
```

## Форматирование

- `#` — только заголовок модуля; `##` — разделы; `###` — подразделы
- `---` между крупными блоками
- Код всегда с языком: ````javascript`, ````bash`, ````typescript`
- ASCII-диаграммы — plaintext без языка
- Комментарии в коде на русском; `// ✅` / `// ❌` для паттернов
- Таблицы с `:--` выравниванием


### Задачи AI-кодеру — формат:

```
Плохая формулировка: > «...»
Хорошая формулировка: > «...»
Формула: что делает + ограничения + конкретные API + версия платформы
```

## Стиль

Тон: технический, прямой, коллеге-архитектору.

**Запрещено:** «Введение в...», «для начинающих», «это важно», «обратите внимание», «не забудьте», hello world примеры, синтаксис без архитектурного контекста, модели вне раздела «Актуальные версии».

**Обязательно:** реальный контекст, actionable выводы, специфичные граничные случаи, развилка джун vs архитектор.

Объём `###`: 150–400 слов не считая код. Объём README.md: ~800–1200 строк.

## AI/ML модули — дополнительно

**«Реальный кейс»** (перед чеклистом): входные данные → гипотеза → результат → вывод противоречащий интуиции.
Только реальный опыт автора. Нет данных — запросить, не придумывать.

**«Антипаттерны»**: решения которые кажутся правильными но являются ошибкой. Не просто «где ломается».
