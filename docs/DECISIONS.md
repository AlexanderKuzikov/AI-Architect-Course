## 2026-08-06: Новые модули 51–52 (API Design, Resilience)

**Контекст:** HANDOFF от 2026-08-06 зафиксировал план A–D. Автор подтвердил: C1 — API design (практика CourtDesk, 26 эндпоинтов REST/JSON для 1С), C2 — Resilience patterns (Bulkhead, Saga, Retry storm). Обе темы числились «архитектурными пустотами» карты курса.

**Решение:** Добавить два модуля (созданы агентом, факты — из практики автора в модулях 49/47/16/17 и knowledge/):
- **51 — API Design для интеграций**: контракт (OpenAPI 3.1), ресурсная модель домена CourtDesk (courts/cases/events/participants/documents), версионирование в URL + Sunset, cursor-пагинация для выгрузок, контракт ошибок (`code/message/details/request_id`), идемпотентность (бизнес-ключ + Idempotency-Key), 1С-специфика (форматы, кодировки, батчи), безопасность (ключи, SSRF-allowlist из инцидента 47). Карта 26 эндпоинтов — обобщённый прототип, требует сверки автором (см. REVIEW_NOTES.md).
- **52 — Resilience Patterns**: таймауты как фундамент, retry с full jitter и бюджетом, Retry Storm, circuit breaker (429 ≠ ошибка), bulkhead, общий rate limit на downstream, saga (orchestration, идемпотентные шаги, состояние в БД), fallback/degraded mode. Реальный кейс — 429-шторм при сборе судебных данных (блокировка IP) и его архитектурное решение.

**Альтернативы:** Отложить C1 до реального списка 26 эндпоинтов (не сделано — автор выбрал «делай на своё усмотрение» с последующей сверкой); закрыть только одну пустоту.

**Trade-off:** Риск расхождения деталей кейса 51 с реальностью (управляется REVIEW_NOTES.md и правками автора) vs закрытие двух пробелов карты сразу.

**Открытые пункты:** сверка карты эндпоинтов 51 с реальным API; пункты REVIEW_NOTES.md.
