# Глоссарий — TypeScript

---

### A

**Ambient Declaration**
Объявление типов для кода, который существует вне TypeScript
(например, глобальные переменные, JS-библиотеки без типов).
Хранится в `.d.ts` файлах. Не генерирует JavaScript-код.

**as const**
Оператор, который говорит TypeScript трактовать значение как
неизменяемое литерал-типы вместо широких типов.
`const x = [1, 2] as const` → тип `readonly [1, 2]` вместо `number[]`.

**Assertion (Type Assertion)**
Явное указание компилятору типа значения через `as Type`.
Не выполняет проверку во время выполнения — только сообщает
компилятору «доверяй мне, я знаю тип». Злоупотребление
нарушает смысл типизации.

---

### C

**Compiler API**
Программный интерфейс TypeScript для анализа и трансформации
TS-кода. Используется для написания инструментов: линтеров,
кодогенераторов, миграций. Открывает AST дерево программы.

**Conditional Type**
Тип, зависящий от условия: `T extends U ? X : Y`.
Позволяет строить сложные вычисляемые типы на основе входных параметров.
Пример: `NonNullable<T>` — убирает `null` и `undefined` из типа.

---

### D

**Declaration File (.d.ts)**
Файл, содержащий только описания типов без реализации.
Используется для типизации JS-библиотек и публикации типов
без исходного кода. Генерируется компилятором при `declaration: true`.

**Decorator**
Синтаксис `@DecoratorName` для добавления метаданных или изменения
поведения класса, метода, свойства или параметра.
Статус: Stage 3 TC39, в TypeScript 5.0 реализованы стандартные декораторы.

**Discriminated Union**
Паттерн объединения типов с общим полем-дискриминатором.
```typescript
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rect'; width: number; height: number };
```
TypeScript автоматически сужает тип внутри `switch/if` по `kind`.

---

### E

**Enum**
Именованный набор констант. В TypeScript существует как числовой,
так и строковый enum. Генерирует реальный JavaScript-объект.
Альтернатива — `as const` объект, не генерирующий лишнего кода.

---

### G

**Generic (Обобщение)**
Параметризованный тип, работающий с разными типами данных
без потери информации о типах. `Array<T>`, `Promise<T>` —
примеры встроенных дженериков. Основа переиспользуемых компонентов.

**Guard (Type Guard)**
Функция или выражение, сужающее тип в блоке кода.
`typeof`, `instanceof` — встроенные guards.
`function isString(x: unknown): x is string` — пользовательский guard.

---

### I

**Index Signature**
Описание типа объекта с произвольными ключами:
`{ [key: string]: number }`. Полезно для словарей,
но теряет точность — все ключи должны иметь одинаковый тип значения.

**Inference (Вывод типов)**
Автоматическое определение типа компилятором без явной аннотации.
`const x = 42` → TypeScript выводит тип `number`.
Хороший код использует inference там, где тип очевиден.

**Interface**
Описание формы объекта или контракта класса. В отличие от `type`,
интерфейсы можно расширять через `extends` и объединять
через declaration merging. Предпочтительны для публичных API.

---

### M

**Mapped Type**
Тип, создаваемый путём итерации по ключам другого типа.
`Partial<T>`, `Required<T>`, `Readonly<T>` — примеры встроенных
mapped types. Позволяют трансформировать существующие типы.

**Module Augmentation**
Расширение типов существующего модуля без изменения его исходников.
Используется для добавления типов к JS-библиотекам или расширения
глобальных типов (например, `Express.Request`).

---

### N

**Narrowing (Сужение типа)**
Процесс уточнения типа переменной в определённом контексте кода
на основе условий, проверок и guards. TypeScript отслеживает
это через control flow analysis.

**never**
Тип, который никогда не имеет значения. Возвращается функцией,
которая всегда бросает ошибку или бесконечно выполняется.
Используется для проверки exhaustiveness в discriminated unions.

**Nullish Coalescing (??)**
Оператор возврата правого операнда если левый `null` или `undefined`.
В отличие от `||` — не срабатывает на `0`, `''`, `false`.

---

### O

**Optional Chaining (?.)**
Безопасный доступ к свойствам потенциально `null`/`undefined` объектов.
`user?.address?.city` — вернёт `undefined` вместо ошибки если
любое звено цепочки `null`/`undefined`.

**Overloading**
Определение нескольких сигнатур функции для разных типов аргументов.
TypeScript выбирает нужную сигнатуру на основе переданных аргументов.
Реальная реализация — одна, с общей сигнатурой.

---

### P

**Pick / Omit**
Встроенные utility types.
`Pick<T, K>` — создаёт тип из T с только указанными ключами K.
`Omit<T, K>` — создаёт тип из T без указанных ключей K.

**Project References**
Механизм разделения большого TypeScript проекта на независимые
подпроекты с инкрементальной компиляцией. Каждый подпроект
имеет свой `tsconfig.json`.

---

### R

**ReturnType**
Utility type для извлечения типа возвращаемого значения функции.
`ReturnType<typeof myFunction>` — не нужно дублировать тип вручную.

---

### S

**Strict Mode**
Набор строгих проверок TypeScript, включаемых через `"strict": true`
в `tsconfig.json`. Включает `noImplicitAny`, `strictNullChecks`,
`strictFunctionTypes` и другие. Обязателен для нового кода.

**StrictNullChecks**
Режим, при котором `null` и `undefined` — отдельные типы,
не совместимые с другими автоматически. Устраняет целый класс
runtime-ошибок «Cannot read property of null».

**Structural Typing**
Система типов TypeScript, при которой совместимость типов
определяется **структурой** (набором полей и методов),
а не именем типа. Объект подходит под интерфейс,
если имеет все нужные поля — явная реализация не нужна.

---

### T

**Template Literal Type**
Тип, строящийся из строковых литералов через шаблонные строки.
```typescript
type EventName = `on${Capitalize<string>}`;
// → 'onClick', 'onChange', etc.
```

**tsconfig.json**
Конфигурационный файл TypeScript компилятора. Определяет:
целевую версию JS (`target`), модульную систему (`module`),
строгость проверок, пути алиасов, включаемые файлы.

**Type Alias (type)**
Псевдоним для любого типа — примитива, объекта, union, intersection.
В отличие от Interface — не поддерживает declaration merging,
но поддерживает сложные вычисляемые типы (conditional, mapped).

---

### U

**Union Type**
Тип, принимающий одно из нескольких значений: `string | number`.
В сочетании с discriminated union и narrowing — мощный инструмент
моделирования состояний системы.

**unknown**
Безопасная альтернатива `any`. Значение типа `unknown` нельзя
использовать без явной проверки типа. Правильный тип для данных
из внешних источников (API, JSON, пользовательский ввод).

---

### Z

**Zod**
Библиотека runtime-валидации с автоматическим выводом TypeScript-типов.
Закрывает gap между статической типизацией (compile-time) и
реальными данными (runtime). Незаменима для валидации API-ответов,
конфигов и пользовательского ввода.
