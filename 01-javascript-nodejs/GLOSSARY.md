# Глоссарий — JavaScript / Node.js

---

### A

**ArrayBuffer**
Объект фиксированного размера в памяти, содержащий сырые бинарные данные.
В отличие от обычных объектов JS, может быть **передан** (не скопирован)
между потоками через `transferList` — это основа zero-copy архитектуры.

**async/await**
Синтаксический сахар над Promises. `async` делает функцию возвращающей
Promise. `await` приостанавливает выполнение функции до разрешения Promise,
не блокируя Event Loop.

---

### B

**Backpressure**
Механизм контроля потока данных в Streams. Возникает когда Readable
генерирует данные быстрее, чем Writable их потребляет. `.pipe()`
управляет backpressure автоматически — при ручной работе нужен
явный контроль через возвращаемое значение `.write()`.

**Blocking**
Синхронная операция, которая удерживает Call Stack и останавливает
Event Loop до своего завершения. Пока выполняется blocking-код —
никакие другие операции не обрабатываются.

---

### C

**Call Stack**
Стек вызовов — структура данных, в которой JS отслеживает выполняемые
функции. Работает по принципу LIFO (последний вошёл — первый вышел).
Когда стек пуст — Event Loop берёт следующую задачу из очереди.

**Callback**
Функция, переданная как аргумент другой функции, для вызова после
завершения асинхронной операции. Первое поколение асинхронности в Node.js.
Проблема — «Callback Hell» при вложенности.

**Callback Hell**
Антипаттерн: глубокая вложенность callback-функций, делающая код
нечитаемым и неподдерживаемым. Решается через Promises или async/await.

**Child Process**
Отдельный OS-процесс, запущенный из Node.js через модуль `child_process`.
В отличие от Worker Threads — полностью изолированный процесс с
собственной памятью. Используется для запуска внешних бинарников.

**CJS (CommonJS)**
Старая модульная система Node.js. Использует `require()` и
`module.exports`. Загружает модули синхронно во время выполнения.
По умолчанию в Node.js до принятия ESM стандарта.

**Circular Dependency**
Циклическая зависимость: модуль A импортирует B, B импортирует A.
В CommonJS приводит к получению пустого объекта вместо экспорта.
Является архитектурным запахом независимо от платформы.

**Config-driven Design**
Архитектурный паттерн, при котором поведение системы определяется
конфигурационным файлом, а не кодом. Позволяет менять поведение
без перекомпиляции и деплоя.

---

### D

**Duplex Stream**
Поток, который является одновременно Readable и Writable.
Пример: TCP socket — можно читать входящие данные и писать исходящие.

---

### E

**Error Class Hierarchy**
Система типизированных классов ошибок, наследующих от `Error`.
Позволяет в обработчике различать типы ошибок через `instanceof`
вместо парсинга строковых сообщений.

**ESM (ES Modules)**
Современная стандартная модульная система JavaScript.
Использует статические `import`/`export`. Анализируется до выполнения,
поддерживает tree-shaking и top-level `await`.

**Event Loop**
Основной механизм Node.js. Бесконечный цикл, который:
1. Проверяет Call Stack (пуст ли)
2. Очищает Microtask Queue полностью
3. Берёт одну задачу из Macrotask Queue
4. Повторяет

**EventEmitter**
Базовый класс Node.js для реализации паттерна publish/subscribe.
Большинство встроенных модулей (fs, http, stream) наследуют от него.
Основные методы: `.on()`, `.once()`, `.emit()`, `.off()`.

---

### G

**Graceful Shutdown**
Паттерн корректного завершения процесса: прекратить приём новых задач,
завершить текущие операции, сохранить состояние, закрыть соединения.
Обрабатывается через `process.on('SIGTERM')` и `process.on('SIGINT')`.

**Garbage Collection (GC)** — автоматическое управление памятью в V8. Освобождает объекты, на которые нет ссылок. В Node.js — поколенческий GC, который может вызывать паузы (STW). Утечки памяти = объекты, на которые остаётся ссылка дольше нужного.

---

### H

**Heap**
Область памяти V8 для хранения объектов. Управляется сборщиком мусора.
Утечки памяти — это объекты в Heap, на которые сохраняются ненужные
ссылки (глобальные переменные, незакрытые подписки EventEmitter).

---

### I

**I/O-bound**
Задача, в которой основное время тразится на ожидание ввода/вывода
(сеть, файловая система, БД), а не на вычисления. Node.js
оптимизирован именно для I/O-bound задач.

**Ignition**
Первый уровень исполнения в V8: интерпретатор. Код читается
и выполняется построчно, без подготовки. Попутно V8 записывает
type feedback — какие типы приходили в аргументах и какие свойства
читались у объектов. Эти наблюдения решают, что и как оптимизировать дальше.

---

### J

**JIT (Just-In-Time)**
Компиляция «в момент выполнения». Движек сначала исполняет код как текст,
а увидев, что функция вызывается повторно, переводит её в машинный код —
и дальше выполняет уже скомпилированную версию. В V8 уровней компиляции три
(Ignition → Maglev → TurboFan), каждый — компромисс между качеством кода
и временем на компиляцию.

---

### L

**libuv**
C-библиотека, на которой построен Node.js. Обеспечивает
кроссплатформенный асинхронный I/O, Event Loop, Thread Pool,
работу с файловой системой, сетью и таймерами.

---

### M

**Macrotask Queue**
Очередь «обычных» задач: `setTimeout`, `setInterval`, I/O callbacks.
За один тик Event Loop берётся одна задача. Приоритет ниже, чем
у Microtask Queue.

**Maglev**
Средний уровень JIT-компиляции в V8 (начиная с V8 11.7). Функция
вызвана примерно 100 раз — этого достаточно, чтобы скомпилировать
быстро, но недостаточно, чтобы тратить время на анализ TurboFan.
Скомпилированный код Maglev заметно быстрее интерпретатора и уступает
TurboFan. В Node.js включён по умолчанию начиная с 22 на поддерживаемых
архитектурах.

**Microtask Queue**
Очередь высокоприоритетных задач: `Promise.then()`,
`queueMicrotask()`. Очищается **полностью** перед следующей
macrotask. Это гарантирует предсказуемый порядок выполнения Promises.

---

### P

**Pipeline**
Архитектурный паттерн последовательной обработки данных через
независимые шаги. Каждый шаг — чистая функция с одним входом
и одним выходом. Шаги можно отключать, заменять и тестировать изолированно.

**Piscina**
npm-библиотека для управления пулом Worker Threads. Обеспечивает
создание, переиспользование воркеров, очередь задач и ограничение
concurrency. Идеальна для пакетных CPU-задач.

**Promise**
Объект, представляющий результат асинхронной операции.
Три состояния: `pending` (ожидание), `fulfilled` (успех),
`rejected` (ошибка). Основа современной асинхронности в JS.

---

### R

**Race Condition**
Ситуация, когда результат зависит от порядка выполнения нескольких
асинхронных операций. Классический пример: проверить существование
файла, затем прочитать его — между этими двумя операциями файл
может быть удалён другим процессом.

**Readable Stream**
Поток, из которого можно только читать. Пример: `fs.createReadStream()`,
HTTP response. Генерирует события `data`, `end`, `error`.

---

### S

**SIGINT**
Unix-сигнал прерывания процесса. Генерируется при нажатии Ctrl+C
в терминале. В Node.js перехватывается через
`process.on('SIGINT', handler)` для graceful shutdown.

**SIGTERM**
Unix-сигнал завершения процесса. Посылается Docker при остановке
контейнера, системными менеджерами (systemd, pm2) при деплое.
Должен обрабатываться для корректного завершения.

**Stream**
Абстракция для работы с последовательными данными по частям (chunks)
без загрузки всего объёма в память. Критично для обработки больших
файлов и медиаданных.

**using / await using**
Конструкция явного управления ресурсами (explicit resource management,
V8 13.6 / Node.js 24). Ресурс освобождается при выходе из блока —
детерминированно, включая случай исключения. `await using` работает
с ресурсами, освобождение которых возвращает Promise.
Заменяет ручной `try/finally` для файлов, соединений и воркеров.

---

### T

**Temporal**
Современный API дат и времени (включён по умолчанию в Node.js 26
с V8 14.6). В отличие от `Date`, умеет календарную арифметику
месяцев и лет и хранит часовую зону явно. `Temporal.PlainDate.from('2026-01-31')
.add({months: 1})` даёт `2026-02-28`, тогда как `Date` с `setMonth(1)`
даёт 3 марта.

**Thread Pool**
Пул потоков libuv (по умолчанию 4) для операций, которые нельзя
сделать полностью асинхронными на уровне OS (DNS lookup, некоторые
fs операции). Настраивается через `UV_THREADPOOL_SIZE`.

**Tick**
Один цикл Event Loop: проверить стек → очистить микротаски →
выполнить одну макротаску.

**Transform Stream**
Duplex поток, преобразующий входные данные в выходные.
Пример: gzip-компрессия, шифрование, парсинг CSV.

**transferList**
Параметр `postMessage()`, определяющий список объектов
(`ArrayBuffer`, `MessagePort`), которые передаются в другой поток
с **передачей права собственности** вместо копирования.
После передачи объект в исходном потоке становится недоступным.

---

### U

**UnhandledPromiseRejection**
Событие, возникающее когда Promise отклонён, но `.catch()` не добавлен.
В Node.js 15+ приводит к завершению процесса с кодом 1.
Перехватывается через `process.on('unhandledRejection')`.

---
### V

**V8**
JavaScript-движок от Google, на котором построен Node.js. Компилирует JS
в машинный код через три уровня: Ignition (интерпретатор) → Maglev (средний
JIT) → TurboFan (оптимизирующий JIT). Версия движка привязана к мажору
Node.js: Node 22 → V8 12.4, Node 24 → V8 13.6, Node 26 → V8 14.6.
Поколения V8 приносят не только скорость, но и возможности языка:
`using`/`await using` (с V8 13.6), Temporal API (с V8 14.6).

**TurboFan**
Верхний уровень JIT-компиляции в V8. Применяется к функциям, вызванным
тысячи раз: сначала строится граф и проверяются типы, затем выполняются
специализации. Работает на предположении, что типы аргументов стабильны
(мономорфны); при нарушении функция деоптимизируется и возвращается
в интерпретатор — это дороже, чем если бы не оптимизировать вовсе.

---

### W

**Worker Threads**
Встроенный модуль Node.js для создания потоков с отдельным
Event Loop и отдельной памятью. Решает проблему CPU-bound задач
в Node.js. Данные между потоками передаются через `postMessage`.

**Writable Stream**
Поток, в который можно только писать. Пример:
`fs.createWriteStream()`, HTTP request. Основные методы:
`.write()`, `.end()`.

---

### Z

**Zero-copy**
Техника передачи данных между потоками без физического копирования
в памяти. В Node.js реализуется через `transferList` в `postMessage`.
Критично для производительности при работе с большими бинарными данными.
