## Контекст (важно для новой сессии)

- Автор коммитит параллельно по ходу работы — перед проверкой статуса
  делать `git pull`/`git fetch`; git status может быть чистым, хотя изменения «ещё вчера были»
- **Не использовать PowerShell Select-String на выводе git** — ANSI-цвета
  ломают матчинг (`git -c color.ui=false ...` для чистого вывода)
- Файлы в репо — LF. После правок edit/write-тулом проверять переносы:
  байтовый конверт CRLF→LF для всех изменённых файлов (иначе git diff показывает весь файл)
- Сборка: `cd scripts && node glossary-links.mjs && node build-html.mjs` (не npm install)
- `course.html` в .gitignore (генерируемый)
- Правило Prompt.md: «Реальный кейс» — только реальная практика автора,
  не выдумывать; модели — только в разделе «Актуальные версии»
- Автор коммитит сам, кроме handoff-сценария (HANDOFF.md — коммит и пуш обязательны)
