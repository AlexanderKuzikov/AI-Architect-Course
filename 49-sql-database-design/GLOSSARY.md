# GLOSSARY — SQL и проектирование схем

## B

**Business Key**  
Бизнес-идентификатор (номер дела, код ОКТМО) — отличается от суррогатного `id`. Уникальность по business key — отдельный constraint, тип — TEXT (ведущие нули, дефисы).

---

## C

**CONCURRENTLY**  
`CREATE INDEX CONCURRENTLY` — построение индекса без блокировки записей. Обязателен для больших таблиц в production.

**Constraint**  
Правило целостности: `UNIQUE`, `NOT NULL`, `CHECK`, `REFERENCES`. Отражает бизнес-семантику, а не «мелочь».

---

## D

**Denormalization**  
Денормализация: хранение дублирующих данных для скорости чтения. Противоположность нормализации. Применяется по измеренной проблеме, цена — риск рассинхрона.

---

## E

**EXPLAIN**  
План запроса PostgreSQL: показывает использование индексов, сканирование, стоимость. Основа решения «какой индекс нужен».

**Embedding Drift**  
Несовместимость векторов после смены embedding-модели. Контроль: `model_version` в каждой строке + фильтрация по актуальной версии.

---

## G

**GIN index**  
Индекс для полнотекстового поиска: `to_tsvector('russian', text)`. Позволяет `@@`-поиск по словам. Для `%LIKE%` — триграммный (`pg_trgm`).

---

## H

**HNSW**  
Индекс приближённого поиска в pgvector (`vector_cosine_ops`). Быстрее IVFFlat на больших данных, строится дольше.

---

## J

**JSONB**  
Бинарный JSON в PostgreSQL. Для «мягких» полей переменного состава. Не валидируется схемой, не участвует в JOIN, индексируется хуже — гибкость за счёт контракта.

**JSONL**  
Формат журнала: одна JSON-запись на строку, append-only. Для инкрементальной истории и аудита без БД. Минус: полный скан при сложных запросах.

---

## M

**Migration**  
Версионируемое изменение схемы: `001_init.sql`, `002_add_column.sql`. Append-only: не редактировать опубликованные, добавлять новые. Отслеживается в `schema_migrations`.

---

## N

**Normalization**  
Нормализация: устранение дублей, разделение на таблицы по зависимостям. Цена — JOIN-ы. Нормализуй по умолчанию.

**NUMERIC**  
Тип для денег и точных чисел. Не FLOAT — последний теряет точность при операциях.

---

## P

**pgvector**  
Расширение PostgreSQL для векторного поиска: `vector(n)`, HNSW/IVFFlat индексы, операторы `<=>`, `<#>`, `<->`. Интеграция векторов с реляционными данными.

**PostgreSQL**  
Production-БД: связи, транзакции, индексы, полнотекст, векторы. Выбор по характеру запросов, не по объёму.

---

## S

**Schema Drift**  
Расхождение схем между окружениями из-за редактирования миграций. Контроль: append-only миграции, тесты, hashes миграций.

**SQLite**  
Встроенная файловая БД. Ноль инфры, single-writer. Для локальных инструментов и прототипов.

**Surrogate Key**  
Суррогатный `id`: `GENERATED ALWAYS AS IDENTITY`. Не бизнес-поле. Бизнес-уникальность обеспечивается отдельным constraint.

---

## T

**TIMESTAMPTZ**  
Тип даты-времени с часовым поясом. Не TIMESTAMP — последний не хранит timezone и ломает расчёты.

**TSVECTOR**  
Полнотекстовый поиск: `to_tsvector('russian', text)` + `@@`-оператор. Для русского языка — конфигурация `russian`.
