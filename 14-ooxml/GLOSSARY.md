# GLOSSARY — OOXML — raw XML внутри DOCX

Термины из модуля по алфавиту. Латиница — первой, затем кириллица.

---

## C

**[Content_Types].xml**  
Реестр типов содержимого ZIP-контейнера DOCX. Каждая часть (part) документа должна быть зарегистрирована здесь с указанием ContentType. Отсутствие регистрации → Word открывает файл с предупреждением или отказывает в открытии.

---

## D

**DEFLATE**  
Алгоритм сжатия используемый в ZIP при генерации DOCX через PizZip. Параметр `compressionOptions: { level: 6 }` — баланс скорости и степени сжатия. Без явного указания PizZip может использовать `STORE` (без сжатия) — файл в 3–5× больше.

**docx (npm)**  
TypeScript библиотека для создания DOCX документов с нуля через декларативный API. Версия 9.5.1 актуальна на март 2026. Не поддерживает редактирование существующих документов и трекинг изменений.

**docxtemplater**  
Node.js библиотека для заполнения `.docx` шаблонов данными. Плейсхолдеры `{field}` вставляются в Word, код рендерит данные. Версия 3.66.3 актуальна на март 2026. Поддерживает циклы (`{#items}...{/items}`) и условия.

**DrawingML**  
Современный XML-формат OOXML для векторной графики и изображений. Namespace `a:` (drawingml/2006/main). Заменил устаревший VML. Используется для вставки изображений (`a:blip`), фигур, диаграмм. Корректно поддерживается в Word, LibreOffice, Google Docs.

---

## E

**ECMA-376**  
Стандарт Office Open XML (OOXML). 5th Edition — актуальная версия. Определяет XML схемы для DOCX, XLSX, PPTX. Обязательный порядок дочерних элементов задан в XSD схемах стандарта. Нарушение порядка → валидный XML, но некорректный OOXML.

**EMU (English Metric Unit)**  
Единица измерения для размеров изображений и объектов в OOXML. 1 дюйм = 914 400 EMU. Используется в DrawingML для `cx` (width) и `cy` (height). Конвертер: `px2emu = px * 9525` при 96dpi.

---

## G

**gridSpan**  
Атрибут `w:gridSpan` в `w:tcPr` — горизонтальное объединение ячеек таблицы. Значение = количество колонок которые занимает ячейка. При использовании gridSpan число `w:tc` в строке меньше числа колонок в `w:tblGrid`.

---

## H

**half-point**  
Единица размера шрифта в OOXML. `w:sz w:val="28"` = 14pt (28 ÷ 2). Конвертер: `pt2halfpoint = pt * 2`. Отдельная от twip система единиц — применяется только к `w:sz` и `w:szCs`.

---

## N

**Namespace resolver**  
Функция-маппер prefix → URI, необходимая для XPath-запросов к OOXML XML. Без неё запрос `//w:p` не находит элементы, так как XPath не знает что `w:` означает wordprocessingml namespace. Обязателен при использовании `xpath.select()` с `@xmldom/xmldom`.

---

## O

**OOXML (Office Open XML)**  
Семейство форматов файлов Microsoft Office: DOCX (Word), XLSX (Excel), PPTX (PowerPoint). Каждый файл — ZIP-архив с иерархией XML частей. Стандартизован ECMA-376. Два профиля: Strict (строгое соответствие) и Transitional (обратная совместимость). Большинство реальных документов — Transitional.

---

## P

**Part (часть документа)**  
Отдельный XML-файл внутри DOCX ZIP-контейнера. Каждая part имеет тип (ContentType) и может иметь relationships к другим частям. Основные части: `word/document.xml`, `word/styles.xml`, `word/settings.xml`.

**PizZip**  
JavaScript библиотека для чтения и записи ZIP-архивов в Node.js и браузере. Основа для прямой манипуляции DOCX: распаковать → изменить XML → запаковать обратно. Форк JSZip оптимизированный для работы с Office форматами.

**python-docx**  
Python библиотека для работы с DOCX. Версия 1.1.x актуальна на март 2026. Поддерживает чтение и запись, но ограничена в низкоуровневом XML доступе — для raw XML манипуляций использовать `lxml` напрямую через `doc.element`.

---

## R

**Relationship (связь)**  
Механизм OOXML для ссылок между частями документа и внешними ресурсами. Определяется в `.rels` файлах. Каждая связь имеет уникальный `Id` (rId1, rId2...) в пределах одной части. В XML ссылка через `r:embed="rId2"` или `r:id="rId3"`.

**.rels файл**  
XML файл в папке `_rels/` описывающий relationships конкретной части. Пример: `word/_rels/document.xml.rels` содержит связи `document.xml` → стили, изображения, гиперссылки. Парный файл к каждому XML который имеет внешние ссылки.

---

## S

**sectPr (Section Properties)**  
Элемент `w:sectPr` — свойства секции: размер страницы, поля, ориентация. Последний элемент в `w:body`. Word требует его наличия. Удаление или перемещение → повреждённый документ. При добавлении параграфов — вставлять перед `sectPr`, не после.

---

## T

**Tracked Changes**  
Механизм отслеживания изменений в DOCX. Удалённый текст — в `w:del/w:delText`, добавленный — в `w:ins/w:t`. Документ с незакрытыми правками содержит одновременно старый и новый текст. При парсинге — явно выбирать какую версию использовать.

**twip**  
Основная единица измерения расстояний в OOXML. 1 twip = 1/20 pt = 1/1440 дюйма. Используется для полей страницы, отступов параграфа, размеров таблиц. Конвертер: `mm2twip = mm * 56.6929`, `cm2twip = cm * 566.929`.

---

## V

**vMerge**  
Атрибут `w:vMerge` в `w:tcPr` — вертикальное объединение ячеек таблицы. Первая ячейка мержа: `w:vMerge w:val="restart"`. Последующие: `w:vMerge` без атрибута. Каждая merged ячейка должна содержать пустой `w:p` — иначе Word повреждает структуру таблицы.

**VML (Vector Markup Language)**  
Устаревший формат векторной графики в OOXML (`v:` namespace). Использовался до DrawingML. LibreOffice поддерживает плохо. Не использовать в новых документах — только DrawingML.

---

## W

**w:b / w:i / w:u**  
Элементы форматирования run в `w:rPr`: bold, italic, underline. Наличие элемента без атрибута = включён. `w:b w:val="0"` = явно выключен (переопределяет стиль). Пустой `<w:b/>` = bold включён.

**w:body**  
Корневой контейнер содержимого документа внутри `w:document`. Содержит параграфы (`w:p`), таблицы (`w:tbl`), и обязательный финальный `w:sectPr`.

**w:p (paragraph)**  
Параграф — основная структурная единица `w:body`. Содержит: опциональный `w:pPr` (первым), один или несколько `w:r` (runs). Каждый элемент `w:tbl/w:tr/w:tc` должен содержать хотя бы один `w:p`.

**w:r (run)**  
Атомарная единица форматированного текста. Один параграф = несколько runs с разным форматированием. Содержит: опциональный `w:rPr` (первым), затем `w:t` с текстом. При парсинге — конкатенировать все `w:t` всех `w:r` параграфа.

**w:t (text)**  
Текстовый узел run. Атрибут `xml:space="preserve"` обязателен если текст начинается или заканчивается пробелом — XML-парсер иначе их обрезает. Отсутствие атрибута на тексте с пробелами = потеря данных.

**Word ML**  
Неформальное название XML диалекта используемого в `word/document.xml`. Основной namespace: `http://schemas.openxmlformats.org/wordprocessingml/2006/main`, префикс `w:`.

---

## Е

**Единицы измерения OOXML**  
Четыре системы единиц в одном документе: twip (поля, отступы), half-point (шрифт), EMU (изображения), процент (ширина таблиц). Смешение систем — распространённая ошибка при ручной генерации XML.

---

## Ш

**Шаблон-пустышка**  
Минимальный `.docx` файл созданный в Word с корректными дефолтными стилями. Используется как основа для генерации документов через docxtemplater или PizZip. Размер ~15 КБ. Содержит все обязательные части (`styles.xml`, `settings.xml`, `theme/`) без необходимости генерировать их программно.
