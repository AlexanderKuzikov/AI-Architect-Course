# GLOSSARY — Multi-model Orchestration

Термины из модуля по алфавиту. Латиница — первой, затем кириллица.

---

## C

**Cascade Filter**  
Архитектурный паттерн: первая (gate) модель выполняет классификацию/детекцию, вторая (main) обрабатывает только объекты, прошедшие порог. Снижает число вызовов дорогой модели до `p × N`, где `p` — доля объектов прошедших gate.

**Concurrency limit**  
Ограничение на количество одновременно выполняемых асинхронных задач. При работе с одной локальной GPU — gate и main модели не параллельны, очередь формируется inference backend'ом. Реализуется через `p-queue` или батч-обработку с `slice`.

---

## D

**Daily limit (RPD)**  
Requests Per Day — суточный лимит запросов провайдера. Сброс привязан к конкретной timezone и точке отсчёта суток (UTC midnight, MSK midnight, rolling window). Тип лимита определяет логику `KeyRotator`.

**Detector Gate**  
Подвид Cascade Filter: gate отвечает на бинарный вопрос «есть ли объект интереса» (yes/no). Требует настройки на recall, а не precision — false negative теряет данные безвозвратно.

---

## F

**Failover**  
Переключение на резервный ресурс при отказе основного. В контексте LLM-pipeline — переключение на другой API key или модель при HTTP 429 / исчерпании квоты.

**False negative (gate)**  
Ошибка gate: объект содержит целевой признак, но gate его отфильтровал. Объект не попадает в main модель — данные теряются необратимо. Критичнее false positive для extraction-задач.

**False positive (gate)**  
Ошибка gate: объект не содержит целевой признак, но gate его пропустил. Результат — лишний вызов main модели. Допустимая ошибка: стоит деньгами, но не теряет данные.

---

## G

**Gate model**  
Первая модель в Cascade Filter. Критерии выбора: минимальная latency, достаточный recall для целевого признака, низкая стоимость вызова (локальная, маленькая). Качество gate определяет полноту данных в output pipeline.

---

## I

**Image tile (vision API)**  
Единица тарификации vision-запросов в облачных API. OpenAI считает tiles 512×512px. Изображение 3000×4000 = ~24 tiles против 1 tile для 512px версии. Прямо влияет на стоимость и latency.

---

## K

**Key Rotation**  
Паттерн последовательного перебора API ключей с отслеживанием остатка квоты каждого. Используется когда поведение API идентично для всех ключей, различается только quota state. Требует timezone-aware сброс счётчиков.

---

## M

**markExhausted()**  
Метод ротатора, принудительно обнуляющий остаток квоты для ключа/модели. Вызывается при получении HTTP 429 — как дополнение к локальному счётчику, который может расходиться с состоянием на стороне провайдера.

**Model Rotation**  
Паттерн переключения между моделями при исчерпании квоты или ошибке. Сложнее Key Rotation: поведение, качество и формат ответа могут отличаться между моделями. Требует `outputNormalizer` и логирования переключений.

**Model Routing**  
Статическое направление запросов к разным моделям по типу задачи (текст → модель A, vision → модель B). Не предполагает fallback. Простейший случай multi-model, не требует quota management.

---

## O

**outputNormalizer**  
Функция постобработки ответа модели для приведения к единому формату. Необходима при ротации между моделями с разным поведением — например, удаление `<think>...</think>` блоков у reasoning моделей перед парсингом JSON.

---

## R

**Race condition (quota)**  
Состояние гонки при параллельных вызовах `getKey()`: два потока получают один ключ до того как счётчик обновился. Результат — превышение квоты и каскад 429. Устраняется через `concurrency limit` или mutex на уровне rotator.

**Recall (gate)**  
Доля реально релевантных объектов, которые gate корректно пропустил. `recall = TP / (TP + FN)`. Для gate в extraction-pipeline recall важнее precision — пропущенный объект теряется, лишний вызов только стоит денег.

**Rolling window**  
Тип лимита: считается N запросов за последние T секунд, а не с начала суток. RPM (requests per minute) у Groq — rolling window 60 сек. Требует иной логики throttling в отличие от daily reset.

**RPD** (Requests Per Day)  
Суточный лимит запросов. Сбрасывается раз в сутки по timezone провайдера.

**RPM** (Requests Per Minute)  
Минутный лимит запросов. Обычно rolling window. Требует throttling между запросами при batch-обработке.

---

## W

**withoutEnlargement**  
Параметр Sharp: запрет увеличения изображений меньше целевого размера. При `maxDimension: 1000` и входном изображении 400px — не масштабирует вверх, оставляет как есть. Предотвращает деградацию качества и раздувание файла.

---

## К

**Каскадный фильтр** → см. *Cascade Filter*

**Квота**  
Лимит использования API за период (сутки, минута). Виды: RPD, RPM, TPD, TPM. Тип квоты определяет архитектуру ротатора: daily quota → счётчик с timezone-reset, rate limit → throttling с rolling window.

---

## О

**Обработка изображений (preprocessing)**  
Обязательный этап перед отправкой в VLM. Включает resize до максимального разрешения (1000px / 1536px по длинной стороне), конвертацию в WebP. Влияет на стоимость (tile billing), latency и качество распознавания.

---

## П

**Паттерн оркестрации**  
Архитектурный шаблон управления несколькими моделями или API. Три базовых класса: Key Rotation (quota management по ключам), Model Rotation (quota management + fallback по моделям), Cascade Filter (оптимизация стоимости через фильтрацию).

---

## Ф

**Fallback-цепочка**  
Упорядоченный список моделей для переключения при отказе основной. Каждый шаг — осознанный trade-off качества: 70B → 32B → 8B снижает качество рассуждений. Без логирования переключений деградация необнаруживаема.
