# GLOSSARY — PDF internals

Термины из модуля по алфавиту. Латиница — первой, затем кириллица.

---

## A

**AcroForm**
Механизм интерактивных форм в PDF. Поля формы хранятся как Widget-аннотации отдельно от content stream. Значения полей извлекаются через `page.getAnnotations()`, а не через `getTextContent()`. Типичные случаи: налоговые декларации, анкеты, договоры с заполненными полями.

---

## C

**canvas (npm)**
Node.js библиотека — нативный C++ binding к libcairo. Необходима для рендеринга PDF через pdfjs-dist в Node.js среде. Требует системных зависимостей (libcairo, libpango и др.). В Docker — усложняет сборку образа.

**CCITTFax**
Формат сжатия растровых изображений в PDF. Используется для чёрно-белых сканов (факс-стандарт). Наличие CCITTFax stream в PDF — признак сканированного документа (class 2, image-only).

**Content stream**
Поток байт описывающий содержимое страницы PDF: PostScript-подобные операторы рисования, позиционирования текста и изображений. Ссылается из объекта страницы через `/Contents`. Текст в content stream — не Unicode строки, а последовательности байтовых кодов глифов.

**Creator**
Поле Info Dictionary PDF: приложение создавшее исходный документ перед конвертацией в PDF. `Creator: "Microsoft Word"` → надёжный text extraction. `Creator: "1C:Enterprise"` → высокая вероятность битого ToUnicode. Первичная диагностика до чтения текста.

**Cross-reference table (xref)**
Таблица байтовых смещений всех объектов в PDF файле. Позволяет парсеру получить любой объект без линейного чтения. Расположена перед `%%EOF`. В incremental update — каждое обновление добавляет новый xref в конец файла.

---

## D

**DPI (dots per inch)**
Разрешение рендеринга PDF страницы. PDF native = 72 DPI. Для документов с мелким шрифтом — минимум 150 DPI. Для OCR/VLM — 200–300 DPI. Формула масштабирования: `scale = dpi / 72`.

---

## E

**EMU** → см. модуль 14. В PDF контексте не используется — PDF использует pt.

**%%EOF**
Маркер конца PDF файла. Парсер ищет файл с конца по этому маркеру. Количество `%%EOF` в файле = количество incremental updates + 1. Множество маркеров — признак документа с историей правок.

---

## G

**Glyph ID**
Числовой идентификатор символа в шрифте. PDF хранит текст как последовательность Glyph ID, не Unicode. Маппинг Glyph ID → Unicode выполняется через ToUnicode CMap или стандартные кодировки. Отсутствие корректного маппинга = text extraction возвращает мусор.

---

## H

**Hybrid PDF**
PDF содержащий и растровое изображение страницы и невидимый текстовый слой. Результат OCR-обработки скана (Adobe Acrobat, ABBYY). Text extraction возвращает OCR-результат — может содержать ошибки распознавания. Класс диагностируется по малому числу символов на страницу при наличии изображений.

---

## I

**Image-only PDF**
PDF где страницы — растровые изображения без текстового слоя. Text extraction возвращает пустую строку. Требует рендер → OCR или рендер → VLM pipeline. Источник: сканер без OCR, фотография документа.

**Incremental update**
Механизм добавления изменений в PDF путём дописывания в конец файла без перезаписи. Каждое обновление добавляет новые объекты и xref. PDF с многими incremental updates может содержать устаревшие объекты. Число обновлений = число `%%EOF` минус один.

**Info Dictionary**
Словарь метаданных PDF: Title, Author, Creator, Producer, CreationDate, ModDate. Устаревший способ хранения метаданных — современные PDF используют XMP. Доступен через `pdf.getMetadata()` в pdfjs-dist.

---

## J

**JBIG2**
Формат сжатия бинарных изображений в PDF. Высокая степень сжатия для чёрно-белых сканов. Как CCITTFax — признак сканированного документа.

---

## M

**MediaBox**
Атрибут объекта страницы PDF: `[x_min, y_min, x_max, y_max]` в pt. Определяет физический размер страницы. A4: `[0 0 595 842]`. При рендеринге — размер canvas = `(x_max - x_min) * scale × (y_max - y_min) * scale`.

**MuPDF**
C библиотека для рендеринга и обработки PDF. JavaScript binding через WASM: `mupdf` npm пакет. Альтернатива PDFium для WASM рендеринга. Версия 1.26.9 актуальна на март 2026.

---

## N

**Native text PDF**
PDF с корректным текстовым слоем и ToUnicode маппингом. Text extraction возвращает точный Unicode текст. Источник: Word → PDF, Google Docs → PDF, LaTeX → PDF. Надёжный для автоматизированной обработки.

---

## O

**Outline (Bookmarks)**
Дерево закладок PDF — иерархическая структура документа (главы, разделы). Доступен через `pdf.getOutline()`. Может использоваться как chunking guide при подготовке документа для RAG.

---

## P

**page.cleanup()**
Метод pdfjs-dist для освобождения ресурсов страницы после обработки. Обязателен при потоковой обработке больших PDF. Без cleanup — память не освобождается и растёт с каждой страницей.

**PasswordException**
Исключение pdfjs-dist при работе с зашифрованным PDF. Два кода: `NEED_PASSWORD (1)` — пароль требуется, `INCORRECT_PASSWORD (2)` — пароль неверен. Обязательно обрабатывать явно в production pipeline.

**pdf-parse**
npm библиотека-обёртка над PDF.js для простого text extraction. Загружает весь PDF в память. Не поддерживает постраничную обработку с управлением памятью и координаты текста. Подходит для прототипов, не для production.

**PDF/A**
ISO 19005 стандарт архивного PDF. Запрещает внешние зависимости, шифрование, JavaScript. Требует встроенных шрифтов с ToUnicode — text extraction надёжнее. Детектируется по XMP метаданным (`pdfaid:conformance`).

**PDF/UA**
ISO 14289 стандарт доступного PDF (Tagged PDF). Требует структурных тегов: заголовки, параграфы, таблицы, alt text для изображений. Открывает структурированное извлечение данных недоступное для неразмеченных PDF.

**PDFium**
PDF rendering engine из Chromium (Google). WASM порт: `@hyzyla/pdfium` и `@embedpdf/pdfium` npm пакеты. Рендеринг без нативных системных зависимостей. Инициализация WASM: 500ms–1s холодный старт.

**pdfjs-dist**
npm пакет Mozilla PDF.js для использования в Node.js и браузере. Версия 5.6.205 актуальна на март 2026. В Node.js: `useWorkerFetch: false, isEvalSupported: false`. Поддерживает text extraction с координатами, рендеринг, метаданные, формы.

**PostScript**
Язык описания страниц от Adobe, предшественник PDF. PDF унаследовал систему координат PostScript: origin (0,0) в нижнем левом углу, ось Y вверх, единица — pt (1/72 дюйма).

**Private Use Area (PUA)**
Диапазон Unicode U+E000–U+F8FF зарезервированный для приватного использования. Символы PDF в PUA при text extraction — признак сломанного ToUnicode: glyph ID попал в PUA вместо реального Unicode codepoint.

**Producer**
Поле Info Dictionary: PDF engine конвертировавший документ в PDF. `Producer: "GPL Ghostscript"` часто означает PostScript маршрут с риском проблем кодировки. `Producer: "Microsoft: Print To PDF"` — надёжный.

---

## S

**scale**
Коэффициент масштабирования при рендеринге PDF страницы. `scale = dpi / 72`. При scale=1.0 — нативное 72 DPI разрешение. Canvas размер = `viewport.width × scale × viewport.height × scale`.

---

## T

**Tagged PDF**
PDF с логической структурной разметкой: иерархия тегов (Document, Sect, P, H1–H6, Table, TR, TD и др.). Требование PDF/UA. Позволяет извлекать документ как структурированные данные, не просто поток текстовых позиций.

**ToUnicode CMap**
Таблица маппинга байтовых кодов глифов на Unicode codepoints, встроенная в объект шрифта PDF. Критична для корректного text extraction. Отсутствие или некорректность ToUnicode → извлечённый текст содержит мусор или символы из Private Use Area.

**transform**
Матрица трансформации TextItem в pdfjs-dist: `[scaleX, skewX, skewY, scaleY, transX, transY]`. `transX` и `transY` — координаты baseline символа. `abs(scaleY)` — размер шрифта в pt. Y координата — от нижнего края страницы (PDF система).

**Type3 font**
Тип шрифта PDF где глифы определены как произвольные векторные программы. Стандартного ToUnicode маппинга нет. Text extraction из Type3 шрифтов — ненадёжен. Встречается в корпоративных системах и старых PostScript-генераторах.

---

## V

**Viewport**
Объект pdfjs-dist описывающий геометрию страницы при заданном scale. Свойства: `width`, `height` (в px). Используется для создания canvas нужного размера и конвертации координат.

---

## W

**Widget annotation**
PDF аннотация типа Widget — интерактивный элемент формы (текстовое поле, чекбокс, radio button). Содержит `fieldName` и `fieldValue`. Доступна через `page.getAnnotations()`.

---

## X

**XMP (Extensible Metadata Platform)**
XML-формат метаданных встроенный в PDF как stream. Современная замена Info Dictionary. Содержит Dublin Core, PDF, XMP схемы. Более полные метаданные включая историю версий документа.

**xref**
Cross-reference таблица или stream в PDF. Хранит байтовое смещение каждого объекта. PDF парсер читает xref первым — получает карту всех объектов. В современных PDF (1.5+) — xref stream с компрессией вместо plain text таблицы.

---

## К

**Кодировка WinAnsiEncoding**
Стандартная кодировка PDF для западноевропейских шрифтов (cp1252). При отсутствии ToUnicode и кириллическом тексте — извлечённый текст некорректен. Признак документа созданного без учёта кириллических кодировок.

---

## П

**Постраничная обработка**
Паттерн обработки больших PDF: загрузить документ один раз, обрабатывать страницы последовательно или батчами, вызывать `page.cleanup()` после каждой. Противопоставляется загрузке всего текста сразу — критично для PDF от 50+ страниц.
